## Validation checks

Schema constraints (primary keys, foreign keys, value domains) are enforced when the
warehouse loads. The checks below cover cricket logic a schema cannot express.

Outside curated competitions, what a check finds is reported as a note on the source:
the match is kept as Cricsheet records it, and anything that relies on the rule (a
model's chase target, for example) handles the exception itself.

| Check | Severity | Status | Notes | Rule |

| `scheduled_overs_within_format` | error | pass | 0 | A limited-overs match is scheduled for no more overs than its format allows (20 in T20 cricket, 50 in ODIs). |
| `innings_wickets_within_limit` | error | pass | 0 | At most 10 wickets fall in an innings (2 in a super over). |
| `innings_totals_match_ball_by_ball` | error | pass | 0 | Innings totals equal the running score after the final delivery (plus any penalty runs awarded outside it). |
| `chase_target_is_first_innings_plus_one` | error | pass | 0 | In limited-overs cricket without a rain rule, the chase target is the first-innings total plus one. |
| `rain_rule_matches_have_revised_target` | error | pass | 0 | Every D/L result carries a revised target on the chase. |
| `win_by_runs_is_consistent` | error | pass | 0 | In limited-overs cricket a win by runs goes to the side batting first, by the exact run margin. Under D/L the chasing side can also win 'by runs' when ahead of par as play is abandoned. |
| `win_by_wickets_is_consistent` | error | pass | 0 | In limited-overs cricket a win by wickets goes to the chasing side, which reached its target. |
| `ties_have_equal_scores` | error | pass | 0 | Limited-overs ties have level scores (without a rain rule); a tie decided by a super over has both super-over innings. |

| `test_wins_are_consistent` | error | pass | 0 | Test results add up: an innings win goes to a side that batted once and outscored the other; a win by runs goes to the side that did not bat last, by the run difference; a win by wickets goes to the side batting last. |
